Database Indexes

Ashmita Pandey · Jul 5, 2025 · Databases

Hi everyone! I'm Ashmita 👋

In the world of software development and system design, performance is everything. Whether you’re building a small web app or a large-scale system with millions of users, how quickly your application can retrieve data matters a lot.

One of the most effective ways to speed up data access in databases is by using Indexes.

Let’s understand this with a real-world scenario.

Imagine This:

You walk into a large library with thousands of books and need to find a book about "Ancient Greek Architecture." Without any system in place, you'd have to browse every shelf and read every title until you find it very time-consuming and inefficient.

But with a catalog or index system, you simply search for your topic in the catalog, find the category and book ID, then walk directly to the correct shelf.

That’s what indexes do in databases. Instead of scanning the entire database (table), an index directs the system to the exact location of the data.

What Are Database Indexes?

A database index is a data structure that allows quick retrieval of records from a table. Instead of scanning each row in a table, the index stores a reference (like a pointer) to the location of rows that match a certain condition.

Real-World Example:

Imagine an employee table with 1 million entries. A query like: 

SELECT * FROM employees WHERE last_name = 'Smith';

Without an index, the database checks every row — a full table scan. With an index on last_name, the system looks up "Smith" in the index, finds the matching references, and directly fetches the data — much faster.

SQL Syntax: 

CREATE INDEX idx_last_name ON employees(last_name);

For multiple columns: 

CREATE INDEX idx_full_name ON employees(first_name, last_name);

How Do Indexes Work?

Behind the scenes, indexes use optimized data structures (like B-Trees) that are sorted and searchable.

Let’s say you have a products table: 

CREATE TABLE products (
  id INT,
  name VARCHAR(100),
  price DECIMAL(10,2)
);

If users often search by price: 

SELECT * FROM products WHERE price < 500;

An index on price helps here: 

CREATE INDEX idx_price ON products(price);

Now, instead of comparing each row's price, the DB engine searches the idx_price index (sorted by price), finds the range, and jumps directly to relevant rows.

Benefits of Using Indexes

  • Speed: Accelerates data retrieval from seconds to milliseconds
  • Efficiency: Reduces CPU and I/O operations
  • Sorting: Helps in fast ORDER BY queries
  • JOIN Optimization: Speeds up joins by indexing foreign keys
  • Selective Filtering: Good for WHERE clauses with high-cardinality columns

Analogy:

Imagine a flight booking system. Without indexes, finding all flights between Delhi and Mumbai requires checking every flight in the table. With an index on departure and destination, the system retrieves relevant entries instantly.

Types of Indexes (with Use-Cases)

Primary Index

Automatically created on primary key. Ensures uniqueness and fastest lookup.

Clustered Index

Sorts the actual table rows. Ideal for range queries like timestamp or price.

Non-Clustered Index

Stores pointers to the row data. Multiple non-clustered indexes are allowed.

Composite Index

Combines multiple columns. Used when WHERE clause filters on both.

Bitmap Index

Best for columns like gender or status in large analytical queries.

Hash Index

Great for exact match lookups in in-memory key-value databases.

Full-Text Index

Efficiently searches inside large text fields, like articles or reviews.

Spatial Index

Used for GIS or maps, indexes latitude and longitude values.

Filtered Index

Applies only to rows matching a condition, like active users. 

CREATE INDEX idx_active_users ON users(status) WHERE status = 'active';

Underlying Data Structures

B-Tree:

  • Balanced, self-sorting tree
  • Efficient for most general-purpose queries
  • Common in MySQL, PostgreSQL

B+ Tree:

  • All values stored in leaf nodes
  • Fast for range scans
  • Often used for large tables

Hash Table:

  • Maps keys to buckets
  • Constant time lookup
  • Not suitable for range queries

Bitmap:

  • One bit per row per value
  • Excellent for analytical filters
  • Example: Gender = Male (1 for male rows)

Smart Indexing Strategies

  • Index columns that are used in WHERE, JOIN, ORDER BY
  • Prioritize high-cardinality fields like user IDs, timestamps
  • Use composite indexes for multi-column filters
  • Avoid indexing low-cardinality fields like boolean
  • Use EXPLAIN to verify index usage
  • Limit index count to reduce storage and update overhead
  • Periodically rebuild indexes on write-heavy tables

Real-World Tip:

If your e-commerce app often filters products by price and category: 

CREATE INDEX idx_price_category ON products(category, price);

This speeds up queries like: 

SELECT * FROM products WHERE category = 'Electronics' AND price < 10000;

Final Thoughts

Indexes are a foundational optimization technique for any high-performance system. They help convert slow, inefficient queries into lightning-fast operations, making the difference between an average app and an excellent one.

However, with power comes responsibility. Over-indexing can hurt write performance and bloat storage. So use them wisely.
