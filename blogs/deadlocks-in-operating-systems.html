Deadlocks in Operating Systems

Ashmita Pandey · Jun 22, 2025 · Operating Systems

Hi everyone, I'm Ashmita!

Understanding how systems handle multiple tasks is crucial to building efficient and reliable software. One of the most important issues in this area is Deadlock. This is a situation where processes are stuck waiting for resources that other processes are holding.

In this article, let's explore Deadlocks in Operating Systems, how they occur, and how they can be prevented, detected, or resolved.

What is Deadlock?

A deadlock is a situation where two or more processes cannot proceed because each is waiting for a resource that the other holds. This creates a cycle of dependencies with no process able to move forward.

Real-World Example:

Imagine two trains on a single track coming from opposite directions. Each train waits for the other to move, but neither can proceed unless the other backs up. Since both are waiting, no train moves. This is a real-life example of deadlock.

Another relatable example is two people trying to pass each other in a narrow hallway. If both move in the same direction at the same time and block each other's path, they may stay stuck, unless one steps aside.

How Does Deadlock Occur?

In an operating system, a process typically:

  1. Requests a resource
  2. Uses the resource
  3. Releases the resource

A deadlock happens when multiple processes are holding resources and waiting to acquire resources held by each other.

Example:

  • Process 1 holds Resource A and wants Resource B.
  • Process 2 holds Resource B and wants Resource A.

Neither process can continue, and both are stuck in a deadlock.

Conditions for Deadlock

A deadlock can occur only if all of the following four conditions are true:

  1. Mutual Exclusion: At least one resource must be non-shareable.
  2. Hold and Wait: A process holding one resource is waiting for additional resources.
  3. No Preemption: A resource cannot be forcibly taken away from a process holding it.
  4. Circular Wait: A set of processes are each waiting for a resource that the next process in the cycle holds.

If any one of these conditions is eliminated, a deadlock cannot occur.

Methods for Handling Deadlock

There are several strategies to handle deadlocks:

  1. Deadlock Prevention or Avoidance
  2. Deadlock Detection and Recovery
  3. Deadlock Ignorance

1. Deadlock Prevention

In this approach, the system is designed to prevent any of the four necessary conditions from holding.

Strategies:

  • Mutual Exclusion: Use it only for truly non-shareable resources like printers.
  • Hold and Wait: Ensure processes request all required resources at once.
  • No Preemption: If a process waits, it must release its currently held resources.
  • Circular Wait: Impose a strict resource ordering. Processes can only request resources in a predefined increasing order.

2. Deadlock Avoidance

This approach uses prior knowledge about future requests.

Banker's Algorithm:

Before granting a resource request, the system simulates the allocation and checks if it leads to a safe state. If it does, the request is granted.

This ensures the system always stays in a safe state, avoiding deadlocks.

3. Deadlock Detection and Recovery

Deadlocks are allowed to occur, but the system must detect and resolve them.

Detection:

  • Use Resource Allocation Graph or Banker's Algorithm periodically to check for deadlocks.

Recovery Techniques:

  • Process Termination:
  • Resource Preemption:

Factors to consider:

  • Priority of process
  • Resources held and required
  • Process progress
  • Type of process (interactive or batch)

Example:

If Process A is using a file and waiting for a printer, and Process B is using the printer and waiting for the file, one process must be terminated or its resource preempted to recover.

4. Deadlock Ignorance

Used by systems like Windows and UNIX.

  • Assumes deadlocks are rare
  • If they occur, restart the system
  • Known as the ostrich algorithm

Useful in simple systems where overhead of prevention and detection is not justified.

Safe State vs Unsafe State

A safe state allows processes to run in an order that avoids deadlocks.

An unsafe state may not lead to a deadlock immediately but has the potential to reach one if resource allocation continues without caution.

Summary

  • A deadlock is a system-wide freeze caused by resource conflict.
  • It occurs when processes wait indefinitely for resources held by each other.
  • Deadlocks require four conditions: mutual exclusion, hold and wait, no preemption, and circular wait.
  • Methods to handle deadlocks include prevention, avoidance, detection and recovery, and ignorance.
  • Tools like Banker's Algorithm and Resource Allocation Graphs are used in handling deadlocks.

By understanding these concepts, we can design systems that are more robust, responsive, and efficient.
