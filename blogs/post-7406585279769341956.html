𝗪𝗵𝗮𝘁 𝗜 𝗻𝗼𝘄 𝗰𝗵𝗲𝗰𝗸 𝗳𝗶𝗿𝘀𝘁 𝘄𝗵𝗲𝗻 𝘀𝗼𝗺𝗲𝗼𝗻𝗲 𝘀𝗮𝘆𝘀 “𝘁𝗵𝗲 𝗔𝗣𝗜 𝗶𝘀 𝘀𝗹𝗼𝘄”

Ashmita Pandey · Dec 16, 2025 · Backend Engineering · Observability

𝗪𝗵𝗮𝘁 𝗜 𝗻𝗼𝘄 𝗰𝗵𝗲𝗰𝗸 𝗳𝗶𝗿𝘀𝘁 𝘄𝗵𝗲𝗻 𝘀𝗼𝗺𝗲𝗼𝗻𝗲 𝘀𝗮𝘆𝘀 “𝘁𝗵𝗲 𝗔𝗣𝗜 𝗶𝘀 𝘀𝗹𝗼𝘄” When I started working on backend systems, I used to jump straight into the code. Over time, I learned that slowness is rarely a code problem. It’s about where the time is going. So before touching the implementation, this is the checklist I follow: 𝟭. 𝗜𝘀 𝗶𝘁 𝗻𝗲𝘁𝘄𝗼𝗿𝗸 𝗼𝗿 𝗯𝗮𝗰𝗸𝗲𝗻𝗱?  • Check TTFB vs total response time  • Slow before first byte = backend  • Slow after = client / network / payload size Many “slow APIs” are actually slow clients. 𝟮. 𝗪𝗵𝗶𝗰𝗵 𝗱𝗲𝗽𝗲𝗻𝗱𝗲𝗻𝗰𝘆 𝗶𝘀 𝗱𝗼𝗺𝗶𝗻𝗮𝘁𝗶𝗻𝗴 𝗹𝗮𝘁𝗲𝗻𝗰𝘆? Break the request into parts:  • Auth / middleware  • Database  • Cache  • External APIs  • Background jobs accidentally running inline One slow dependency = slow API. 𝟯. 𝗗𝗮𝘁𝗮𝗯𝗮𝘀𝗲 𝗳𝗶𝗿𝘀𝘁, 𝗮𝗹𝘄𝗮𝘆 𝗔𝘀𝗸:  • Is this query indexed?  • Is it doing more work than needed?  • N+1 queries?  • Full collection scan hiding behind small data? Most backend slowness lives here. 𝟰. 𝗔𝗿𝗲 𝘄𝗲 𝗯𝗹𝗼𝗰𝗸𝗶𝗻𝗴 𝘄𝗵𝗲𝗻 𝘄𝗲 𝘀𝗵𝗼𝘂𝗹𝗱𝗻’𝘁? Common mistakes:  • Calling external services synchronously  • Heavy computation inside the request cycle  • Waiting for background tasks to finish Async APIs with sync work are still slow. 𝟱. 𝗖𝗼𝗹𝗱 𝘀𝘁𝗮𝗿𝘁𝘀 𝗮𝗻𝗱 𝗰𝗼𝗻𝗻𝗲𝗰𝘁𝗶𝗼𝗻 𝗼𝘃𝗲𝗿𝗵𝗲𝗮𝗱 Check for:  • Lambda or container cold starts  • New DB connections per request  • DNS or TLS setup on every call These don’t show up in code reviews but hurt latency. 𝟲. 𝗥𝗲𝘁𝗿𝗶𝗲𝘀, 𝘁𝗶𝗺𝗲𝗼𝘂𝘁𝘀, 𝗮𝗻𝗱 𝘀𝗶𝗹𝗲𝗻𝘁 𝗳𝗮𝗶𝗹𝘂𝗿𝗲𝘀  • Is the request retrying under the hood?  • Are timeouts too high?  • Is one failed dependency stalling everything? Retries without limits create hidden latency. 𝟳. 𝗣𝗮𝘆𝗹𝗼𝗮𝗱 𝘀𝗶𝘇𝗲  • Over-fetching data  • Large JSON responses  • Uncompressed responses Latency isn’t only compute. Bytes matter. 𝟴. 𝗟𝗼𝗴𝘀 𝗯𝗲𝗳𝗼𝗿𝗲 𝗮𝘀𝘀𝘂𝗺𝗽𝘁𝗶𝗼𝗻𝘀 Check:  • Request duration breakdowns  • Slow request logs  • P95 and P99, not averages Averages lie. Tail latency is what users feel. Slow APIs are rarely fixed by faster code. They’re fixed by understanding where the time is actually spent.
