An API responds in ~100ms for users in the US, but takes ~2 seconds for users in India.

Ashmita Pandey · Apr 3, 2026 · System Design · Networking

An API responds in ~100ms for users in the US, but takes ~2 seconds for users in India. At first glance, it looks like a backend bug. In reality, it’s a standard system design problem. When users are far from your servers, latency increases due to network distance, routing, and multiple hops. Optimizing code alone won’t fix this. What actually works is designing systems for global scale: 1. Region-based deployments Serve users from the nearest geographic region instead of a single centralized server. 2. Content Delivery Network (CDN) Cache static and frequently accessed data closer to users to reduce backend dependency. 3. Caching layer (Redis / API Gateway) Minimize repeated database calls and reduce response time. 4. Database replication Route read operations to the nearest replica while keeping writes controlled. 5. Geo-routing Automatically direct users to the closest available server. 6. API optimization Reduce payload size, enable compression, and use efficient protocols like HTTP/2. What seems like a performance issue in code is often a distribution problem in architecture. This is what real-world system design looks like.
