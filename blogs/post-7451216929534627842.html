Your service is slow… but CPU usage is low. What do you check first?

Ashmita Pandey · Apr 18, 2026 · Backend Engineering · Observability

Your service is slow… but CPU usage is low. What do you check first? It feels counterintuitive. If CPU isn’t busy, why is the system slow? Because most performance issues aren’t about doing too much work… they’re about waiting too long. Here’s how I approach it: 1. Thread / Process State  • Are workers blocked on locks?  • Waiting on I/O?  • Stuck in queues? If your system isn’t using CPU, chances are it’s idle… but not by choice. 2. External Dependencies  • Database latency  • Third-party APIs  • Internal microservices A slow dependency can quietly drag your entire system down. 3. Database Bottlenecks  • Missing indexes  • Inefficient queries  • Connection pool limits Databases are often the hidden gravity well of latency. 4. Lock Contention  • Shared resources causing blocking  • Poor concurrency design Low CPU + high latency often points to threads waiting their turn. 5. I/O Wait  • Disk reads/writes  • Network delays  • Logging overhead I/O is the silent saboteur. It slows everything without spiking CPU. 6. Queue Backlogs  • Message queues piling up  • Thread pools saturated  • Requests waiting before execution Sometimes the system isn’t slow… it’s just not getting to work yet. 7. Resource Limits (Other than CPU)  • Memory pressure  • File descriptors  • Network bandwidth CPU is just one piece of the puzzle. If CPU usage is low, your system isn’t overloaded… it’s waiting somewhere. And the real skill is figuring out where that wait begins.
