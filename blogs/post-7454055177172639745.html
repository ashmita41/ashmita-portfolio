Dead Letter Queues are one of those small concepts that quietly save production systems.

Ashmita Pandey · Apr 26, 2026 · System Design · Messaging

Dead Letter Queues are one of those small concepts that quietly save production systems. When a message fails to be processed Maybe the data is malformed Maybe a downstream service is down What do you do? Drop it? Retry forever? Neither. You send it to a Dead Letter Queue (DLQ). A DLQ is a separate queue for messages that fail after a defined number of retries. They don’t block your main flow. They don’t keep consuming resources. They wait until someone inspects and fixes them. Without DLQs • One bad message can block the entire queue • Continuous retries can waste resources With DLQs • The main system keeps running • Failures are isolated and easier to debug Any async system at scale should include a DLQ. Would love to know how others handle failed messages in their systems.
