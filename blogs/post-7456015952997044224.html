What happens when you upload a file to Amazon S3?

Ashmita Pandey · May 1, 2026 · System Design · Cloud Computing · AWS

What happens when you upload a file to Amazon S3? Let’s understand it step by step 👇 At a high level, S3 works with two core layers: • Bucket (metadata layer) • Object (data + metadata) Now here’s the actual flow: 1. You create a bucket The bucket is not where your file physically lives It exists in the metadata layer and acts as a logical container It defines namespace, region, policies, and access control 2. Client sends a PUT request When you upload a file, Your application sends an HTTP PUT request to S3 (often signed using AWS Signature V4) 3. S3 checks: – Does the bucket exist? – Do you have permission to upload? – It validates:   IAM policies / bucket policies  ACLs (if used)  Request signature 4. Request is routed internally S3 routes the request to the appropriate partition based on the object key (This is part of how S3 achieves horizontal scaling) 5. Metadata is prepared Before storing the file, S3 creates metadata like: – Key (object name) – Size, content-type – Timestamps, storage class – Version ID (if versioning is enabled) 6. Data gets stored The object data is written to multiple storage nodes across Availability Zones S3 ensures high durability (11 9’s) by replicating the data 7. Unique Object ID is generated S3 assigns an ID that links your file’s data with its metadata It is an internal identifier that maps the object’s data to its metadata S3 provides strong read-after-write consistency for PUT operations 8. Metadata store is updated The metadata layer is updated with object location, version, and attributes This enables fast lookup and retrieval S3 is not just a storage service It’s a distributed system that separates compute, metadata, and storage layers That’s why it works reliably even at massive scale!
