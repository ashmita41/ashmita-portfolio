HTTP just got its first new standardized request method in more than 20 years.

Ashmita Pandey · Jul 6, 2026 · Networking · HTTP

HTTP just got its first new standardized request method in more than 20 years. It's called QUERY. At first, it might seem like just another HTTP method. But it actually solves a problem that many backend engineers have encountered while designing APIs. Suppose you're building a product search endpoint where users can filter by: • Multiple brands • Price range • Categories • Rating • Availability • Sorting options Traditionally, we'd use a GET request. http GET /products?brands=Apple,Samsung&minPrice=30000&maxPrice=80000&rating=4... This works well for simple queries, but as more filters are added, the URL quickly becomes long, difficult to read, and harder to maintain. It can also run into URL length limitations imposed by browsers, proxies, or servers. To avoid this, many APIs use POST instead and send the filters as a JSON request body. {  "brands": ["Apple", "Samsung"],  "price": {   "min": 30000,   "max": 80000  },  "rating": 4,  "inStock": true } While this makes the request much cleaner, there's one issue. A search operation doesn't create or modify anything. It's simply asking the server to return data. Using POST works technically, but it doesn't accurately describe the intent of the request. That's where QUERY comes in. It allows clients to send a request body while explicitly indicating that the operation is read-only. In other words: • You get the flexibility of a request body. • The request still represents a read operation. • API semantics become clearer and more consistent. This may seem like a small addition, but it's significant because it's the first new standardized HTTP request method in more than two decades. Even technologies that have been around for decades continue to evolve as new engineering challenges emerge. Official RFC: https://lnkd.in/ez6ZZyyr Have you ever used POST for search endpoints because GET wasn't sufficient? I'd be interested to know how you've approached this in your APIs.
