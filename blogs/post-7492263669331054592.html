Sometimes, the fastest database query is the one you never execute.

Ashmita Pandey · Aug 9, 2026 · System Design · Databases

Sometimes, the fastest database query is the one you never execute. That's the basic idea behind Bloom Filters. Before performing an expensive lookup, a Bloom Filter helps answer a simple question: Could this key exist? The answer can be: Definitely not or Probably yes If it's definitely not present, we can skip the lookup. If it's probably present, we perform the actual lookup. The interesting part is that Bloom Filters don't store the actual data. They use a bit array and multiple hash functions to keep just enough information to determine whether an element could exist. This makes them extremely memory efficient. But there is a trade-off. Bloom Filters can have false positives, but they can never have false negatives. This simple idea is useful in systems such as Cassandra, Bigtable, HBase, Redis, and other large-scale systems where avoiding unnecessary disk or database reads can make a significant difference. I recently wrote an article explaining how Bloom Filters work, why false positives happen, how they save disk I/O, and where they are used in real-world systems. If you've heard about Bloom Filters but never quite understood how they work, check it out.
