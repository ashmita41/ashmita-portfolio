iPhone 17 at ₹50K during Big Billion Days 👀

Ashmita Pandey · Aug 19, 2026 · System Design · Distributed Systems · Retail Tech

iPhone 17 at ₹50K during Big Billion Days 👀 Haha, hold on. Forget the ₹50K for a second 😂 Let’s say you open the app, see “Only 5 left”, and hit Buy Now. So do 10,000 other people. Now the interesting question: How does the backend decide who actually gets those 5 iPhones? It’s not as simple as: → Check inventory → If stock > 0, place the order → Reduce stock Because thousands of requests can reach the backend almost at the same time. Two requests could read: stock = 1 before either one updates it. And suddenly, the same iPhone could be sold twice 😬 So the system needs to make the inventory update atomic. For example: UPDATE inventory SET stock = stock - 1 WHERE product_id = X AND stock > 0 If the update succeeds: → Inventory reserved → Continue with the order If it affects 0 rows: → Someone else got it → Sorry, better luck next time 🥲 But inventory is only the beginning. What if the payment succeeds but the order request times out? What if the user clicks Pay twice? What if the payment fails after the inventory was reserved? Now you need to think about: • Race conditions • Database transactions • Inventory reservation • Atomic operations • Idempotency • Payment/order consistency • Distributed systems All of this happens behind a button that simply says: “Buy Now.” Simple to use. Not so simple to build. That’s the fun part of backend engineering. Also, who else is waiting for BBD? 👀
