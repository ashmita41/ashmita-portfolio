MCP sounds complicated until you see the actual message an agent sends.

Ashmita Pandey · Oct 27, 2026 · AI · MCP · Agents

MCP sounds complicated until you see the actual message an agent sends. It's about one line of JSON. When an agent connects to an MCP server, the first thing it does is ask what tools exist: {"jsonrpc":"2.0","id":1,"method":"tools/list"} The server replies with each tool's name, a plain-English description, and a JSON Schema for its inputs: { "name": "get_order_status", "description": "Get the current status of an order by its ID", "inputSchema": {"type": "object", "properties": {"order_id": {"type": "string"}}, "required": ["order_id"]} } That description is the part most people underestimate. The model never sees your code. It picks a tool purely by reading that one sentence, so a vague description means wrong tool calls no matter how good the model is. Now a user asks "where's my order 4417?". The model decides this tool fits, and the client sends: {"jsonrpc":"2.0","id":2,"method":"tools/call", "params":{"name":"get_order_status","arguments":{"order_id":"4417"}}} The server runs your function and sends the result back as content the model reads before it answers. That's the whole loop: list, pick, call, read. It runs over stdio for local servers and over HTTP for remote ones. What this changes about how I build MCP tools: I write descriptions for the model, not for humans. I say when to use the tool and when not to. I keep inputs small and typed. An enum beats a free-text string because the model can't invent a value that doesn't exist. I return errors as readable text. "Order 4417 not found, check the ID" lets the agent recover. A raw 500 makes it guess. Once you've seen the JSON, MCP stops being a buzzword. It's just an API contract that a model reads. #AI #MCP #AIAgents
