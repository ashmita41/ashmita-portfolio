HTTP Status Codes: The Language Between Clients and Servers

Originally published Jul 7, 2025

  • Backend
  • Engineering Practices
An on-site adaptation of Ashmita’s earlier article, not a verbatim republication.

A status code tells the client what happened before it reads a response body. That makes codes a small but useful part of the API contract: client behavior, retry logic, and monitoring all depend on them.

Distinguish progress, success, and redirection

Informational 1xx responses are interim. In the 2xx family, 200 reports success, 201 commonly marks a created resource, and 202 means work was accepted without promising it has finished. The 3xx family covers redirects as well as cache revalidation. For example, 304 lets a client reuse its cached representation rather than downloading another copy.

Choose an error code that tells the caller what to do

A 401 response usually means valid credentials are missing or need refreshing; 403 means the server refuses the request. A 429 tells the caller to slow down. A 503 signals temporary unavailability and may carry a Retry-After hint. Whether to retry also depends on the operation: sending a write twice after a timeout can repeat a side effect. Use the status code, the response details, and the operation’s retry rules together.
