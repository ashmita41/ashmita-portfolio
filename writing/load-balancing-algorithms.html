Load Balancing Algorithms with Real-World Examples

Originally published Jul 22, 2025

  • System Design
  • Infrastructure
An on-site adaptation of Ashmita’s earlier article, not a verbatim republication.

Three healthy servers can sit behind the same load balancer and still see very different workloads. An even request count tells you little when one request finishes in milliseconds and another holds a connection for a minute.

Start with what you know about the fleet

Round robin cycles through the available backends. It is a good baseline when servers have similar capacity and requests cost about the same. Weighted round robin sends more traffic to larger backends, but the weights are configuration, not a view of current load. Least connections routes toward backends with fewer active connections; that signal is more useful when connections roughly represent the work still in progress.

Watch for the cases your signal misses

Latency-aware routing can steer traffic away from a slower backend if measurements are fresh enough. A client-IP hash can offer affinity for sessions, but many clients behind the same proxy can land on one server. Whatever strategy you choose, test with uneven requests and a failed backend. The routing rule only helps if health checks can first remove the server that should receive nothing.
