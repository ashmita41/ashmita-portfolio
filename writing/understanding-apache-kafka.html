Understanding Apache Kafka and Its Role in Modern System Design

Originally published Jan 23, 2026

  • System Design
  • Distributed Systems
  • Kafka
An on-site adaptation of Ashmita’s earlier article, not a verbatim republication.

Kafka stores events as logs that consumers can read at their own pace. The key difference from a work queue is that reading an event does not automatically remove it, allowing other applications to read it independently.

Find the unit of order

A topic is split into partitions. Each partition has its own order, and offsets identify positions within that partition. Events about the same customer or order can share a key so that they are routed together under a consistent partitioning scheme. Do not assume order across the whole topic. Adding partitions improves potential parallelism, but a hot key can still concentrate load on a single partition.

Give each use case its own progress

An order event might drive notifications and analytics. Separate consumer groups can track their progress independently, so a delay in analytics need not stop notifications. Consumers in the same group share partitions to divide work, and a group can reread retained events when it needs to rebuild derived state. For external side effects, decide whether the consumer can safely repeat an operation before choosing when to commit its offset. An offset records progress; it does not prove that a separate database write or notification succeeded.
